# 安全設計・データ保護

Status: **Proposed** / 2026-10-20

GitPick は開発者のローカル作業ツリーと設定ファイルを扱うため、機能の便利さよりデータの保全を優先する。

## 変更の境界

| 操作 | 初期版の扱い |
| --- | --- |
| `.gitignore` / `.gitattributes` を編集 | 差分確認を必須とする |
| ファイル本体の削除・移動 | しない |
| `git add`, `git rm --cached` 等で index を変更 | 初期版ではしない。将来は別承認 |
| commit / push / force-push | しない |
| Git の過去のコミットを書き換え | しない |
| 管理者権限・外部送信 | 原則不要・なし |

## 強制する不変条件

1. **プレビュー前に変更しない。** `plan` と `apply` は別の処理。
2. **対象外を触らない。** 選択パスから決めた Git ルート・管理設定ファイル以外を書き換えない。
3. **他人のルールを保持する。** コメント、順序、改行コード、ユーザー管理領域を極力保持。GitPick の管理領域だけを編集。
4. **最新状態で再検証する。** 承認時から状態が変われば適用を停止してプレビューを作り直す。
5. **途中失敗に対処する。** 変更前の内容を復元できること、部分成功を隠さないことを設計要件とする。
6. **繰り返しても変わらない。** 同じ設定の再適用で重複行や無限に変わる差分が生じない。
7. **コマンドを安全に実行する。** シェル連結は禁止。信頼できる `git` 実行ファイルに引数配列で渡し、パスを厳密に区別。
8. **重要な設定を勝手に変えない。** Git の global / system 設定、ユーザーの既存 ignore / attributes、その他リポジトリ設定は無断編集しない。

## 想定する失敗

- `.gitignore` と `.gitattributes` の両方を更新する途中で失敗
- 別プロセスが設定を書き換える / ファイルが削除される
- Git LFS が未導入、外部コマンドが異常終了
- Windows の権限、文字エンコード、ロック、ネットワークドライブの障害
- 管理対象のパスに shell metacharacters や newline を含む
- symlink / junction が Git ルート外を指す
- tracked / ignored / LFS の判定が競合する
- 改行や BOM、既存のコメントを変更してしまう

## 実装上の安全策（受け入れ条件）

- 変更前の内容と更新予定のハッシュを保持し、競合時に勝手に上書きしない。
- 既存内容はバイト単位で保全する方針。編集した箇所と必要最小限の改行だけ更新する。
- 書き込みは同一ボリューム上の一時ファイルを利用し、可能なら原子的置換。複数ファイルにまたがるときは復旧手段を検証する。
- ファイル名は可能な限り NUL 区切りで扱い、ログでは機微なローカルパスの無断収集をしない。
- 「設定は追加できたが tracked のまま」「LFS ルールは追加できたが既存 commit は通常 Git のまま」を成功と誤認させない。
- エラー後にユーザーが変更を確認・復旧できる結果画面を用意する。

## サポート外・要確認

- Git履歴移行は破壊的影響が大きいので後期フェーズの別機能として検討する。
- セキュリティ上の問題やプライバシーに関わる事象は公開 Issue に機密情報を貼らない。報告窓口は公開前に決定する。
- 重大な仕様変更はドキュメントとテストケースを同時に更新する。
