# 操作仕様（Product behavior）

Status: **Proposed** / 2026-10-20

## 利用者向けコマンド

| 操作 | 既定の動作 | 注意点 |
| --- | --- | --- |
| Git 管理から除外 | 対象パスに対応するルールを `.gitignore` に提案 | 追跡中のファイルはこの操作だけでは追跡解除されない |
| Git LFS で管理 | 対象ファイルに絞った `.gitattributes` ルールを提案 | 既存コミットとインデックスは別途確認 |
| 状態を確認 | `git ls-files`, `git check-ignore`, `git check-attr` 等で評価 | worktree によって解釈が異なる |
| 設定を解除 | GitPick が作成したルールのみ候補として提示 | 外部で定義されたルールを削除・上書きしない |
| リポジトリ解析 | 不要生成物 / 大容量ファイルの候補を提示 | MVP 後の機能 |

初期版では **設定編集を先に実装**し、追跡解除や LFS 再登録は確認が必要な別アクションとして段階的に追加する。

## 処理フロー

1. 選択パスから所属 Git リポジトリを検出。外部パス、未初期化、bare repository は説明を表示して停止。
2. Git の追跡状態、`.gitignore` と `.gitattributes` の既存ルールを検査。
3. ファイル単位で変更案を作り、重複・競合・既存のユーザールールを判定。
4. 変更差分と影響範囲を表示（tracked の場合は必ず警告）。
5. 明示的な承認後、変更対象がレビュー時から変わっていないか再確認し適用。
6. Git コマンドで結果を検証し、成功・部分失敗・追加作業を表示。

## ignore の具体的な扱い

- MVP は **リポジトリルートの `.gitignore`** に、リポジトリルートからの相対パスで固定したルールを基本とする（`/Library/` 等）。
- 特殊文字（空白、`#`, `!`, `*`, `?`, `[`, `]`, バックスラッシュなど）は Git のパターン規則に沿って処理する。Windows のパス区切りは変換する。
- フォルダー指定は末尾 `/` を使う。ルールによって巻き込む対象数を表示する。既存の子ディレクトリ `.gitignore` や否定パターンにも留意。
- 追跡中のファイルは `.gitignore` を追加しても追跡中のまま。別操作で `git rm --cached -- <path>`（フォルダーなら条件付きで `-r`）を **確認後に**実行する機能を後日実装。作業ツリーファイルは削除しない。
- ユーザーの既存ルールは改変しない。GitPick が追加する行は専用管理セクションに記録し、同じ操作の二重追加を防ぐ。
- 外部の ignore 設定により既に除外されている場合は、不要な新規ルールを増やさず根拠を示す。

## LFS の具体的な扱い

- 既定は **選択した個別ファイルへのルール**。拡張子全体を対象とする `*.psd` のような広い指定は別途ユーザーが選択した場合だけ。
- フォルダーの LFS は無条件に全ファイルを一括指定しない。対象一覧をスキャンし、個別・拡張子別・全体（明示操作）の選択肢を示す（MVP 後）。
- 可能な場合 `git lfs track --filename` や `git lfs track --dry-run` を利用し、正しいパターンと変更範囲を検証する。
- 有効な LFS 指定は `git check-attr filter -- <path>` などで検証する。Git LFS が未導入なら操作を拒否し、導入案内を示す。
- `.gitattributes` に容量条件は書けない。**50 MiB 超は注意、100 MiB 超は GitHub 向けの強い警告**とする（閾値は将来ホスト別に設定可能にする）。
- 既に index にあるファイルには再正規化が必要になる場合がある。対象を明示して確認後に実行する。広範な `git add --renormalize .` の自動実行はしない。
- 過去のコミットを LFS に変えるには履歴移行が必要。**MVP は履歴移行を実行しない**。状況説明と公式手順への案内のみ。

## 「解除」の定義

設定解除 ≠ Git の過去の状態への完全な巻き戻し。

- GitPick が生成した **対象ルール**だけを消せる。
- 別のパターンが一致していれば依然として ignored / LFS になることを事前告知。
- 既存コミット、LFS オブジェクト、index の再正規化は自動で戻らない。
- 手動で編集された管理セクションでは、意味が曖昧な行を勝手に削除しない。

## 多数選択・境界ケース

- 複数リポジトリにまたがる選択は、**リポジトリごとに別プラン**として表示し一括適用しない。
- ネストしたリポジトリ、サブモジュール、リンク、junction、別 worktree、UNC パスを安全に扱う。曖昧なものは拒否して理由を表示。
- 空フォルダー、読み取り専用ファイル、未保存変更、競合中、特殊文字を含む名前でクラッシュしない。
- `.git` やリポジトリの外のファイルを管理対象にしない。
- リポジトリルートが見つかっても、選択パスと実際の作業対象が異なる場合は拒否。

## まだ実装しないもの

GitHub ログイン、Push 操作、過去のコミット書き換え、AI による自動判定、すべての生成物の無確認自動除外。これらは将来の提案段階。
