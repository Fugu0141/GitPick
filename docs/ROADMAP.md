# ロードマップ

Status: **Initial proposal** / 2026-10-20

GitPick は機能をまとめて完成させるより、Git操作の正しさを小さく検証してから Explorer と接続する。各フェーズの達成条件は Issue で管理する。日付の確約ではない。

## Phase 0 — 基盤整備

**目標:** アプリの動作を伴わず、開発開始の準備を完了する。

- README、基本設計、振る舞い、安全要件、テスト計画を確定
- Rust workspace / core / CLI のひな形
- Windows ネイティブ拡張ビルドの最小検証
- CI（フォーマット、lint、unit test）の導入
- ライセンスとバイナリ配布方針の決定

**Exit:** 基本ビルドと Git を使うテストがローカル / CI で再現できる。

## Phase 1 — Core / CLI MVP

**目標:** エクスプローラーの外から安全に操作できる。

- ローカル Git リポジトリ発見、サブモジュール等の境界判定
- tracked / ignored / LFS 状態の判定
- 単一ファイル・フォルダーの ignore ルール提案
- 単一ファイルの LFS ルール提案
- 差分プレビュー、明示的な apply、重複防止
- 主要な境界条件と異常系のテスト

**Exit:** サンプル Git リポジトリを使い、正しいルールを生成でき、元のユーザー設定を破損しない。

## Phase 2 — Explorer 統合 MVP

**目標:** Windows 11 の右クリックから単一項目の除外・LFS・状態確認が可能。

- `IExplorerCommand` によるメニュー登録
- shell から別プロセスへの安全な選択パス受け渡し
- 操作前確認 UI と結果表示
- インストール・アンインストール・更新の検証

**Exit:** 実機でエクスプローラーを固めずに正しく起動・適用・解除できる。

## Phase 3 — 日常利用向け品質改善

- 複数選択、複数リポジトリ、フォルダー内のLFS候補選択
- tracked の除外・既存ファイルの LFS 再登録を明示的に補助
- 大容量ファイル検出と 50 / 100 MiB の警告
- 多言語対応、アクセシビリティ、パフォーマンス測定
- 実際のプロジェクト（Unity、.NET 等）での試験

## Phase 4 — 推奨・診断機能

- Unity / .NET / Node.js 等のプロジェクト判別
- 生成物・キャッシュ・大容量ファイルの候補提案
- 公開テンプレートに基づくルール提案と競合検知
- Push 前の診断（自動 Push はしない）

**重要:** 自動解析はファイルを勝手に除外する機能ではない。必ず根拠と影響範囲を表示して承認を得る。

## 意図的な非目標

- Git GUI クライアントの全面的な代替
- GitHub 専用サービス化
- 初期版でのコミット履歴一括書き換え
- ユーザーが理解できない無確認の自動修正
